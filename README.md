 OPNsense lab на Hyper-V

Домашняя лаборатория: межсетевой экран OPNsense 26.7 в виртуальной машине Hyper-V.

## Схема сети

`Интернет → Default Switch (WAN) → OPNsense → LAN-PRIVATE (LAN) → тестовая ВМ с Windows 10`

## Что сделано

- [x] Установка OPNsense на виртуальный диск (UFS), настройка порядка загрузки
- [x] Два сетевых адаптера: WAN (Default Switch) и LAN (частный коммутатор)
- [x] Назначение интерфейсов, DHCP на LAN, мастер первоначальной настройки
- [x] Алиас `myservers` и правило Block для LAN
- [x] Порядок правил: Block выше Allow
- [x] Чтение логов в Firewall → Log Files → Live View
- [ ] Алиас портов, статический DHCP, DNS Override
- [ ] VLAN, WireGuard, Suricata

## Проблема и решение

Правило Block не срабатывало на часть адресов. Причина: у тестовой ВМ было два сетевых адаптера, и трафик шёл мимо OPNsense.
Нашёл командами `route print` и `tracert` на клиенте, лишний адаптер отключил.

## Чему научился

1. Правила читаются сверху вниз, срабатывает первое подходящее.
2. После Save в алиасах нужен Apply, иначе файрвол использует старую версию.
3. Файрвол видит только трафик, который идёт через него.
4. Диагностика по шагам: настройка → что реально загружено → путь трафика.
